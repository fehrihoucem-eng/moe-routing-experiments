How far back does routing history reach?

Every predictor here is built only from tokens the model has already finished — t−1, t−2, t−4, t−8 — and a lag is not a horizon: t−4 was known 200 ms ago at 20 tok/s, so reaching further back costs nothing in lead time. The only question is whether older tokens say anything t−1 has not already said.

A token eight back still names as many of the router's experts as layer popularity does. Routing does not decorrelate inside this window — it decays to a high floor. That floor is the trap: a predictor can look strong alone and still be redundant.

Routing memory is longest in the middle of the stack

Coverage@8 against lag, averaged within each third of the stack. The x-axis is log₂ lag, so equal spacing is equal doubling — a straight line is exponential decay. Flatter means longer memory.

The mid-stack does not merely persist more strongly from t−1 — it decays more slowly, holding of its t−1 coverage at t−8 where both ends hold about 60%. Across the 39 layers the correlation between a layer's t−1 coverage and its t−8/t−1 ratio is +0.65: layers that remember the previous token also remember the one before that.

Unions: older tokens extend the list, they do not re-rank it

Two ways to rank a union, because “does older history help?” is two questions. Priority is the literal set union, newest token first — at K=8 it is t−1 by construction, so it can only say whether older tokens fill a surplus budget better than popularity does. Vote weights a slot by decaylag−1 times its gate and sums, so older tokens can reorder t−1's own eight — the only rule that can improve the ranking, and the only one that can lose.

Voting cannot beat copying at K=8 — the three-lag vote's fold range straddles zero and the two-lag vote loses in all five folds. Whatever a slot's recurrence across t−1, t−2 and t−4 says about it, the router's own gate at t−1 already said it better. And the union saturates at t−4: by t−8 the slots on offer have almost all been named already.

An unplanned result

— at K=8 for cross-layer + t−1, against — for the published winner on this same grid — — paired, consistent in all five folds, and larger than any gap in the original study.

same
Both have the layer horizon and the same cross-layer term.
different
The published combined mixes in the fitted transition table P(Eₜ | Eₜ₋₁); this mixes in the raw copy of the previous token's eight slots.
why
That study's own finding was that copying beats learning the transition — then it built the combination out of the learned table anyway, because a copy ships no table to mix. Its gate vector is a distribution, and mixing that is both legal and much better. The weight lands at against w = 0.4 there, because the copy puts all its mass on eight slots and needs only a nudge.

This is not what the experiment set out to measure. Treat it as a lead: train only, one tuned weight, and the test split for corpus_v1 is already spent.

Before this goes any further

  • The gains above K=8 are budget, not accuracy. Every union result says the same thing in different words: give a predictor 16 slots and older tokens are good candidates for the extra 8. Nothing here says routing is more predictable than the first study found — at the router's own top-k, it is not.
  • The grid moved, so the baselines moved with it. Restricting to tokens with 8 predecessors costs about 0.3pp uniformly: the published combined predictor scores 40.26 here against 40.57 on the shallower grid. Do not read a row of this page against a row of the other one.
  • Prefetch is still simulated. No number here is a latency — all 10,240 experts fit in this box's VRAM. What changed is that filling a budget of 16 from t−1 ∪ t−2 ∪ t−4 costs no table and no lead time, where the published K=16 result needed a 2.6M-cell cross-layer table inside 1.25 ms.
  • Train only, 80 prompts, one corpus, greedy at temp=0. The paired fold statistics above are not a substitute for a second corpus, and the held-out split is not read here.
